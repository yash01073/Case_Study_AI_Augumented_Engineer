## Overview

**TaskBridge API** is the core backend service for the TaskBridge platform — a multi-tenant B2B SaaS application that helps engineering teams manage projects, track progress, and stay informed through automated notifications and a full audit history.

Key capabilities:

| Capability | Description |
|---|---|
| **Project Management** | Full lifecycle management (DRAFT → ACTIVE → COMPLETED → ARCHIVED) with enforced status transitions |
| **Notifications** | Tenant-scoped event-driven notifications delivered to teams and users |
| **Audit Trail** | Immutable, tamper-evident log of all state-changing operations per tenant |
| **Multi-tenancy** | Hard tenant isolation enforced at the JWT, service, and database layers |
| **Security** | Stateless JWT authentication, deny-by-default authorization, and IDOR prevention |

## Architecture

The service follows a **package-by-feature, layered architecture** with strict one-way dependency rules.

```
HTTP Request
     │
     ▼
┌─────────────────────────────────┐
│       API Layer (Controllers)   │  ← HTTP mapping, @Valid, response codes
└────────────────┬────────────────┘
                 │
┌────────────────▼────────────────┐
│   Application Layer (Services)  │  ← Business rules, @Transactional, tenant assertion
└────────────────┬────────────────┘
                 │
┌────────────────▼────────────────┐
│      Domain Layer (Entities)    │  ← Aggregate roots, domain methods, state machines
└────────────────┬────────────────┘
                 │
┌────────────────▼────────────────┐
│  Infrastructure (Repositories)  │  ← Spring Data JPA, all queries tenant-scoped
└─────────────────────────────────┘
```

### Security & Tenant Isolation Flow

```
JWT Token (Authorization header)
     │
     ▼
JwtAuthFilter → validates signature, expiry, issuer
     │
     ├─► TenantContext  (thread-local: tenantId, userId)
     └─► MDC            (structured log enrichment: tenantId, userId, traceId)
                 │
                 ▼
         Controller reads TenantContext
                 │
                 ▼
         Service enforces tenant ownership  ──► 404 on mismatch (no tenant enumeration)
                 │
                 ▼
         Repository applies tenant predicate in every query
```

### Key Design Decisions

- **Never trust tenant ID from request body or path** — always derived from JWT claim `tenant_id`.
- **Return 404 (not 403)** when a resource exists but belongs to a different tenant, to prevent tenant enumeration attacks.
- **Domain objects are not exposed directly** — dedicated request/response DTOs (Java `record`) form the API contract.
- **State transitions are enforced in the domain** — invalid transitions throw `IllegalStateException`, translated to `409 Conflict`.
- **Flyway manages schema** — DDL is version-controlled and never auto-generated by Hibernate at runtime.

## Setup

### Prerequisites

| Tool | Minimum Version |
|---|---|
| JDK | 21 |
| Maven | 3.9 |
| PostgreSQL | 15 |
| Git | 2.x |

### 1. Clone the repository

```bash
git clone https://github.com/your-org/taskbridge-api.git
cd taskbridge-api
```

### 2. Create the database

```sql
CREATE DATABASE taskbridge;
CREATE USER taskbridge WITH PASSWORD 'taskbridge';
GRANT ALL PRIVILEGES ON DATABASE taskbridge TO taskbridge;
```

### 3. Configure environment variables

The application resolves secrets from environment variables. Set the following before running:

| Variable | Description | Default (dev only) |
|---|---|---|
| `DB_USERNAME` | PostgreSQL username | `taskbridge` |
| `DB_PASSWORD` | PostgreSQL password | `taskbridge` |
| `JWT_SECRET` | HMAC-SHA signing key (≥ 32 chars) | `change-me-in-production-must-be-at-least-32-chars` |
| `JWT_ISSUER` | Expected JWT issuer claim | `taskbridge` |
| `JWT_EXPIRATION_MS` | Token lifetime in milliseconds | `3600000` (1 hour) |

> ⚠️ **Never** use the default `JWT_SECRET` in staging or production environments.

PowerShell example:

```powershell
$env:DB_USERNAME   = "taskbridge"
$env:DB_PASSWORD   = "s3cur3p@ss"
$env:JWT_SECRET    = "super-secret-signing-key-min-32-chars!!"
$env:JWT_ISSUER    = "taskbridge"
```

## Build Instructions

### Compile only

```bash
mvn compile
```

### Package (skip tests)

```bash
mvn package -DskipTests
```

### Package with tests

```bash
mvn package
```

### Run locally

```bash
mvn spring-boot:run
```

The API will start on `http://localhost:8080`.

### Run the packaged JAR

```bash
java -jar target/taskbridge-api-0.0.1-SNAPSHOT.jar
```

### Database migrations

Flyway runs automatically on startup. To run migrations manually:

```bash
mvn flyway:migrate
```

## Test Instructions

### Run all tests

```bash
mvn test
```

### Run a specific test class

```bash
mvn test -Dtest=ProjectServiceImplTest
```

### Run a specific test method

```bash
mvn test -Dtest=ProjectServiceImplTest#should_deleteProject_when_projectBelongsToTenant
```

### Test coverage report

```bash
mvn verify
```

> Unit tests use H2 in-memory database and do not require a running PostgreSQL instance.

### Test categories

| Suite | Location | Purpose |
|---|---|---|
| `ProjectTest` | `projects/domain` | Domain entity state machine, transition rules |
| `ProjectServiceImplTest` | `projects/service` | Service logic, tenant isolation, cross-tenant denial |

## API Reference (Quick Summary)

All endpoints require a valid `Authorization: Bearer <jwt>` header. The JWT must include a `tenant_id` claim.

| Method | Path | Description |
|---|---|---|
| `POST` | `/api/v1/projects` | Create a new project |
| `PUT` | `/api/v1/projects/{id}` | Update project name/description |
| `PATCH` | `/api/v1/projects/{id}/status` | Transition project status |
| `GET` | `/api/v1/projects?teamId={teamId}` | List projects by team |
| `DELETE` | `/api/v1/projects/{id}` | Delete a project |

### Project Status Lifecycle

```
DRAFT ──► ACTIVE ──► ON_HOLD ──► ACTIVE
                │                   │
                ▼                   ▼
            COMPLETED           CANCELLED
                │
                ▼
            ARCHIVED
```
